# Phase 2, slice D: virtual waiting room, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An event can switch on a waiting room: customers queue first come first served, a worker admits them in controlled batches up to a capacity, they see their position live, and only an admitted customer can hold a seat.

**Architecture:** One Redis sorted set per event holds the queue (score: join time from the `Clock`), a second one holds the admissions (score: expiry time, so an admission is a key with a TTL and a slot frees itself). A pure domain policy decides who is admitted next and how many; one Lua script applies the decision atomically and enforces the capacity, so two workers cannot over-admit. A worker job runs the policy every second. The position streams over SSE by polling the Redis state (like the simulation progress stream). `BookingsService.hold` asks the waiting room for the caller's admission when the event has one.

**Tech Stack:** NestJS, node-redis (Lua), Drizzle, Zod, Angular (signals), Playwright, Vitest.

**Spec:** [Phase 2 design, slice D](../specs/2026-11-13-phase-2-async-and-scaling-design.md)

## Global Constraints

- Time only from the injected `Clock` (`CLOCK`); no `Date.now()` in new code, domain code included.
- No fallback when Redis fails: the error propagates (fail fast). The admission job logs a failed tick (error name only) and retries on the next one, like `HoldExpiryJob`.
- Identity only from the verified token; no route takes a user ID from the client. Logs carry IDs only.
- Constants: `WAITING_ROOM_STATE`, `ADMISSION_TTL_SECONDS` (300), `ADMISSION_BATCH_SIZE` (10), `MAX_ADMISSION_CAPACITY` (1000), `ADMISSION_INTERVAL_MS` (1000), stream cap `MAX_WAITING_ROOM_STREAMS` (200, all replicas together), `WAITING_ROOM_POLL_MS` (1000), `WAITING_ROOM_STREAM_MAX_LIFETIME_MS` (600_000): `as const` dictionaries or named constants, imported by the tests (`pnpm audit:magic`).
- AGENTS.md applies: no `vi.mock`, no `any`, no `as unknown as`, relative imports end in `.js`, modules import each other through `index.ts` only, English docs, Conventional Commits straight on `main`, hooks never skipped, `pnpm check` green before every commit.
- A migration is generated by drizzle-kit, never edited by hand, and is an expand step (nullable column, no backfill needed). The migration commit carries `[braucht Live-Migration]` in its subject, like the `ticketReady` one.
- Run `df -h` before the first image build (Task 8).

## Deviations from the spec (decided here)

- **One column, not two.** `events.waiting_room_capacity integer null`: null means no waiting room, a number is the capacity. `waiting_room_enabled` could only contradict it. A check constraint keeps the number positive.
- **The admission policy is a pure function over the queue head** (`planAdmissions`), the Lua script only applies it and re-checks the capacity. Who is next and how many stay in domain code; the atomic capacity bound stays in the adapter.
- **The settings route is `PUT /api/events/:id/waiting-room/settings`** (organizer of the event, or admin), and `CreateEventRequest` takes the same optional capacity.

## Interfaces (exact signatures)

```ts
// packages/shared/src/waiting-room.ts
export const WAITING_ROOM_STATE = {
  NONE: 'NONE',
  WAITING: 'WAITING',
  ADMITTED: 'ADMITTED',
} as const;
export const MAX_ADMISSION_CAPACITY = 1000;
export const WaitingRoomCapacitySchema = z.number().int().min(1).max(MAX_ADMISSION_CAPACITY);
export const WaitingRoomStatusSchema = z.object({
  state: z.enum(WAITING_ROOM_STATE),
  position: z.number().int().min(1).nullable(), // 1-based, only while WAITING
  waiting: z.number().int().min(0), // length of the queue
  admittedUntil: z.iso.datetime().nullable(), // only while ADMITTED
});
export const SetWaitingRoomRequestSchema = z.object({
  capacity: WaitingRoomCapacitySchema.nullable(),
});
// EventSummarySchema gains: waitingRoomCapacity: WaitingRoomCapacitySchema.nullable()
// CreateEventRequestSchema gains: waitingRoomCapacity: WaitingRoomCapacitySchema.nullable().default(null)

// apps/api/src/modules/waiting-room/domain/admission-policy.ts (pure, no I/O)
export const ADMISSION_BATCH_SIZE = 10;
export function planAdmissions(input: {
  capacity: number;
  admitted: number; // live admissions now
  head: readonly string[]; // user IDs, front of the queue first
  batchSize: number;
}): string[]; // the first min(capacity - admitted, batchSize, head.length) of head, never negative

// apps/api/src/modules/waiting-room/domain/waiting-room-store.ts (the port)
export interface WaitingRoomStore {
  /** Idempotent: a user who is queued or admitted keeps their place. */
  join(eventId: string, userId: string, now: Date): Promise<void>;
  /** Removes the user from the queue and from the admissions. */
  leave(eventId: string, userId: string): Promise<void>;
  status(eventId: string, userId: string, now: Date): Promise<WaitingRoomStatus>;
  isAdmitted(eventId: string, userId: string, now: Date): Promise<boolean>;
  snapshot(
    eventId: string,
    now: Date,
    headSize: number
  ): Promise<{ admitted: number; head: string[] }>;
  /** Moves the given users from the queue to the admissions, atomically, never past `capacity` live admissions. Returns the users that moved. */
  admit(input: {
    eventId: string;
    userIds: readonly string[];
    capacity: number;
    now: Date;
    expiresAt: Date;
  }): Promise<string[]>;
}

// apps/api/src/modules/waiting-room/waiting-room.service.ts
@Injectable()
export class WaitingRoomService {
  join(eventId: string, userId: string): Promise<WaitingRoomStatus>; // 404 not visible, 409 no waiting room
  leave(eventId: string, userId: string): Promise<void>;
  status(eventId: string, userId: string): Promise<WaitingRoomStatus>;
  /** ForbiddenException unless the event has no waiting room or the user holds a live admission. */
  assertAdmitted(eventId: string, userId: string): Promise<void>;
  setCapacity(eventId: string, capacity: number | null, caller: AuthUser): Promise<EventSummary>;
  /** One tick for every event with a waiting room; returns the number of users admitted. */
  admitDue(): Promise<number>;
}
```

Redis keys: `waiting-room:<eventId>:queue` (sorted set, member = user ID, score = join time in ms), `waiting-room:<eventId>:admitted` (sorted set, member = user ID, score = expiry in ms). Both keys get a `PEXPIRE` of one day on every write, so the keys of a deleted event vanish.

Routes (all `ROLE.CUSTOMER` unless noted; the user is the token's user):

| Route                                       | Answer                                                                                    |
| ------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `POST /api/events/:id/waiting-room`         | 200 `WaitingRoomStatus`; 404 event not visible; 409 the event has no waiting room         |
| `GET /api/events/:id/waiting-room`          | 200 `WaitingRoomStatus` (`NONE` when not queued)                                          |
| `DELETE /api/events/:id/waiting-room`       | 204; leaves the queue and gives the admission back                                        |
| `GET /api/events/:id/waiting-room/stream`   | SSE of `WaitingRoomStatus`, on change only; ends after `ADMITTED` or `NONE`; 503 over cap |
| `PUT /api/events/:id/waiting-room/settings` | 200 `EventSummary`; organizer of the event or admin (scoped like `setStrategy`)           |

## Review Focus

- **Capacity bound.** Parallel `admit` calls (two workers, ten parallel calls) never leave more live admissions than the capacity. Test with real Redis; hand check: drop the capacity check in the script, the parallel test must fail.
- **Order.** Users join in clock order and leave the queue in that order. Same-millisecond joins fall back to the member order of the sorted set (documented limit, see the shortcut note in the store).
- **Hold gate.** A hold on a waiting-room event without a live admission answers 403 and writes nothing; an event without a waiting room behaves as before; the simulator's sandbox events never have one. A hold with an expired admission answers 403.
- **No double entry.** One user cannot be queued twice or queued while admitted, also when two joins run in parallel (the script drops a queued member that is already admitted).
- **Identity and ownership.** Every route reads the user from the token; a customer cannot read or change another user's place; the settings route answers 403 for a customer and 404 for an event outside the caller's scope.
- **Stream slots** are given back on every way a stream ends (reuse `SlotLimiter`, same test as the simulation stream).
