# Agent Rules

Canonical instructions for every coding agent in this repo. `CLAUDE.md` only imports this file.
Context, architecture and phases: [docs/PLAN.md](docs/PLAN.md). State and open points:
[docs/BACKLOG.md](docs/BACKLOG.md). Read all three at the start of a session. Use `pnpm`, never `npm`
or `yarn`.

A rule that a tool can check is checked by a tool (`pnpm check`, hooks, CI), not by the agent.

## 1. Layers (enforced by `pnpm depcruise` and ESLint)

The system is a modular monolith plus a worker (see
[ADR 0001](docs/adr/0001-modular-monolith-and-worker.md)).

- **`packages/shared`**: Zod schemas, inferred types and `as const` dictionaries. Nothing else: no
  functions, no classes, no Node modules, npm only `zod`, nothing from `apps/*`. It is the single
  source of truth for every contract (REST, SSE, queue messages).
- **`apps/api`** (NestJS): one folder per module under `apps/api/src/modules`. A module's
  `domain/` folder (or `src/core` for logic that several modules share) is pure, deterministic
  business logic without I/O: no `@nestjs/*`, no Drizzle, no Redis, no queue, no Node core module,
  no `Date.now()`, no random. It imports only other domain code, `packages/shared` and `zod`, and it
  defines the ports (interfaces) that adapters implement. Controllers are thin adapters: parse the
  input with a Zod schema, read the user from the verified token, delegate to the domain, format the
  answer. Database, Redis, queue and Keycloak are adapters behind ports.
- **Time comes from an injected `Clock`.** Hold TTL, expiry and the waiting room are testable
  without waiting.
- **Module boundaries.** A module imports another module only through its `index.ts`. No circular
  dependencies. Test support a module offers to other specs lives in its `testing/` folder: specs
  import it directly (the worker through `@app/api/<module>/testing`), production code never does.
- **`apps/worker`** (NestJS standalone application): queue consumers, scheduled jobs and the
  simulator. It reuses the API's modules through their `index.ts`; the API never imports the worker.
- **`apps/web`** (Angular: standalone components, signals, RxJS for streams, Tailwind): components
  never use `HttpClient`; only `*.service.ts` and `*.store.ts` do. No runtime import from
  `apps/api` or `apps/worker`; contracts come from `packages/shared`.
- **SoC beats DRY.** Extract only on the third identical use (Rule of Three). No speculative
  abstractions (YAGNI).
- **Fail fast.** No silent `catch`, no fallback data in production paths.
- **Filter, search and aggregate in PostgreSQL**, never by loading whole tables into Node.
- **Strict types:** no `any`, no `@ts-ignore`, no `as unknown as`, no `export *`, no `unknown` as a
  parameter or return type (parse at the boundary with Zod). Every type assertion except `as const`
  needs a `// SAFETY: <invariant>` comment. Derive types with `z.infer`, never write a parallel type.
- **Constants:** a value that steers logic (status, role, strategy) is an UPPER_SNAKE value in an
  `export const X = {...} as const` dictionary and is imported everywhere, tests included
  (`pnpm audit:magic`).
- No module mocking in tests (`vi.mock`): pass dependencies in (a port, a fake) or use MSW.
- NestJS is ESM-only here: relative imports end in `.js`, use `import.meta.dirname`. Its docs index
  for agents: <https://docs.nestjs.com/llms.txt>.

## 2. Product invariants

1. **No double booking**, except in the explicit comparison strategy `naive`.
2. **Identity only from the verified token**, never from an ID the client sends. Every query on
   user-owned data filters by ownership on the server; PostgreSQL row-level security is the second
   layer.
3. **Idempotency:** payment and queue consumers are protected by idempotency keys. Name the key in
   the contract.
4. **State transitions** of a booking happen only through the state machine in the domain; every
   transition is stored.
5. **Env only through the config module** (`apps/api/src/config`, validated with Zod); nothing else
   reads `process.env`. Never read, print or commit `.env*` files; only `.env.example` is tracked,
   and it lists every variable (`pnpm docs:generate` checks that).
6. **No personal data in logs**, only IDs. Structured JSON lines (pino), no `console`.
7. **No real network calls in unit tests:** an unmocked request fails the test (MSW in
   `vitest.setup.ts`; `HttpTestingController.verify()` in the web tests).
8. **UI states:** every async view handles empty, loading, error (with retry) and pending (disabled
   controls, no double submit).
9. **Verify before deciding:** never rely on memory for library APIs, versions, image tags or
   limits. Read the current docs or the installed package.
10. **Portable docs:** relative links, no absolute machine paths, no test counts. Docs change in the
    same commit as the code they describe.
11. **Migrations** are generated by drizzle-kit and never edited by hand. They are backward
    compatible (expand, backfill, contract) and run automatically on deploy.
12. **Presentation:** the product is called `ticketmaster-klon`. No third-party logo or brand asset;
    the UI footer and the README say that it is unofficial and not affiliated. Docs, commits and code
    describe the system, never why it exists or who looks at it. The users named in docs are the
    roles of the domain: customer, organizer, admin.
13. **Language:** code, comments, commits, README, ADRs and docs are English.

## 3. Workflow

**Phases.** The work is split into phases ([docs/PLAN.md](docs/PLAN.md)). Stop after each phase and
report: state, deviations from the plan, open points. Each phase starts in a fresh session.

**Pre-flight (before touching code)**, in a few lines: scope, what is explicitly out of scope, the
command that proves success. Skip it for copy changes, pure styling and Markdown.

**Vertical slices.** Build each feature end to end: contract (`packages/shared`), backend, frontend,
test, docs. Not layer by layer. Smallest diff that passes.

A bug in behavior starts with a test that fails for the bug and passes after the fix. Purely visual
fixes get no test: check them in the browser. UI changes are inspected in a browser (chrome-devtools
MCP or Playwright) before they count as finished. UI work follows [PRODUCT.md](PRODUCT.md) and uses
shared UI primitives and semantic design tokens, never ad-hoc colors.

**Commits and pushes** go directly to `main`; there are no feature branches. One topic per commit,
Conventional Commits, imperative subject. Commit and push only when the hooks are green; never skip
them (`--no-verify`), never force-push, never stage `.env*`. The hooks do not run everything CI runs:
after a push look at `gh run list --branch main --limit 1` and fix a red run before starting new work.

**Docs map.** A change to a path listed in `docs/docs-map.json` needs its document in the same
commit, or `Docs: n/a, <reason>` in the commit message. Add a mapping when a new documented area
appears (database schema, deploy scripts). `docs/PLAN.md` holds context only: no dates and no
status; state belongs in `docs/BACKLOG.md`. Generated tables are written by `pnpm docs:generate`.

**Decisions.** Small decisions are yours: choose the simplest option that fits the plan and give the
reason in the commit message. Larger ones get an ADR in `docs/adr/` (MADR, numbered, with the
rejected alternatives). Dependencies may be added without asking: verify the current docs first,
keep the set small, record why in the commit message. Ask the user only for things that change
scope, cost or data protection, or that are hard to undo.

## 4. Test philosophy

- Assert behavior, not markup: text, roles, calls and returned values.
- One behavior, one test, at the lowest layer that can show it. Do not repeat an assertion on a
  second layer (unit, route, database, end to end).
- A test must be able to fail. For logic with branches and for every guard, break the code by hand
  (flip a condition, remove the guard) and check that a test dies; a surviving change is a missing
  test or dead code. The reverse also holds: a test that can be deleted without letting any hand
  mutation survive adds nothing, so delete it.
- Auth tests live in the test file of each protected route: wrong role and foreign resource both
  answer 403.
- The concurrency test is mandatory: parallel bookings of the same seat, per strategy, asserting
  the number of double bookings.
- Test files are named `*.spec.ts` and sit next to the code. Setup that repeats a third time moves
  to the package's `testing/` folder.
- The number of tests is a report, never a goal.

## 5. Commands

| Command                          | Purpose                                                                                         |
| -------------------------------- | ----------------------------------------------------------------------------------------------- |
| `pnpm check`                     | typecheck, ESLint, dependency-cruiser, knip, jscpd (2 %), magic-string and docs audit, Prettier |
| `pnpm test`                      | unit tests of all packages (Vitest, offline)                                                    |
| `pnpm e2e`                       | builds the Compose stack, runs the Playwright specs in `apps/web/e2e`, tears the stack down     |
| `pnpm dev`                       | API and web in watch mode                                                                       |
| `pnpm build`                     | builds every package                                                                            |
| `pnpm db:up` / `pnpm db:down`    | Postgres and Redis for tests (Docker)                                                           |
| `docker compose up --build`      | the whole local stack, web on port 8080                                                         |
| `pnpm docs:generate`             | rewrites the generated tables in the docs                                                       |
| `pnpm format`                    | Prettier (staged files are formatted by lint-staged)                                            |
| `pnpm audit:duplication:details` | lists the duplicates when `pnpm check` reports too many                                         |
| `pnpm depcruise:graph`           | writes `architecture.mmd`, the module graph                                                     |

Guards around the agent: `.claude/settings.json` denies reading env files and editing the lockfile;
the PreToolUse hook blocks `--no-verify`, force pushes, deleting remote branches and access to
secret files; the Stop hook requires a green `pnpm check` when code changed. Husky runs lint-staged
and `pnpm check` before a commit, the docs-map audit on the commit message and `pnpm test` before a
push.

## 6. Definition-of-Done receipt

At the end of every feature (not for docs, config or review fixes):

```markdown
### DoD: <task>

- [x] Contract: schemas in `packages/shared` (or not needed)
- [x] Tests: <n> passing, `pnpm check` green, no real network calls
- [x] Invariants: ownership, idempotency, state machine, logs (as applicable)
- [x] Observability: spans/metrics for new paths (or not needed)
- [x] UI: four states, verified in browser (or not applicable)
- [x] Docs: updated (or not needed)
- [ ] Out of scope / open: <list>
```
